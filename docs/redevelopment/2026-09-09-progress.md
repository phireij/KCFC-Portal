# KCFC Portal Redevelopment Progress — 2026-09-10

## Branch

`redesign/mobile-first-v2`

Draft PR: #1 — **Redevelopment: mobile-first shell and schedule foundation**

Production `main` remains unchanged.

## Completed in the active redevelopment branch

### 1. Responsive application shell

- New official KCFC navy / royal-blue visual foundation.
- Mobile navigation is exactly five primary destinations: Home, Schedule, Community, Updates, More.
- Horizontal scrolling navigation has been removed from the new shell.
- Desktop uses a persistent left sidebar with role-aware utility and leadership links.
- Mobile More opens as a bottom sheet and contains Availability & Polls, Resources, Inbox, Profile, Accounting when authorized, and Leadership/Admin when authorized.
- Reading-size defaults were normalized toward the approved 15–17 px body range while preserving user-selectable larger accessibility sizes.

### 2. Schedule experience

- Existing detailed duties/assignment page is preserved as `LegacyDuties.tsx` for regression safety.
- `/duties` is a member-oriented Schedule hub.
- **All schedule** shows chronological Mass dates and expandable published ministry rosters.
- **My ministry** shows the member's own liturgical assignments and community duties in one timeline.
- Whole-schedule browsing includes Upcoming/all-date controls, search, liturgical ministry filters, a dedicated Where I Serve filter, empty-state recovery, month grouping and expandable roster detail.
- My Ministry has separate **Upcoming** and **History** views.
- Published-roster notifications can deep-link directly to My Ministry.

### 3. Home experience

- Existing dashboard is preserved as `LegacyDashboard.tsx` for reference/regression safety.
- Home is member-first rather than admin-statistics-first.
- Home highlights next published assignment, next KCFC Mass, availability-response status, action-needed availability, leadership approval alerts, upcoming Mass dates, announcements and quick links.

### 4. Liturgical availability and assignment workflow

- Existing poll implementation is preserved as `LegacyPolls.tsx` for compatibility.
- Multi-Mass availability requests remain compatible with existing Firestore poll and response records.
- Members can select every Mass where they are available and revise their response while the request remains active.
- Leader mode includes request creation, response-progress monitoring, availability matrix, assignment builder, explicit final roster publication and unpublish.
- New availability cycles use explicit publication state.
- Editing an assignment after publication returns the roster to unpublished review state.
- Initial publication, revision publication and unchanged republication use tested shared creator plans.
- Revised publication targets only affected members.
- Legacy publication compatibility remains available for historical records.

### 5. Community Directory

- Community Directory uses the mobile-first KCFC design language.
- Search, Core/Regular member filtering and multi-ministry filtering are cleaner on phones.
- General directory cards do not expose private member contact details.

### 6. Updates / Announcements

- Updates is rebuilt in the new mobile-first design language.
- Announcement publication uses shared audience eligibility, communication routing and notification-record helpers.
- KCFC Inbox remains the durable record even when routine secondary alerts are muted.
- PWA token collection follows recipient-level routing and de-duplicates FCM targets.
- External connectors remain disabled and public website synchronization remains inactive.

### 7. KCFC Inbox

- Inbox is the durable source of truth for operational communication.
- Mobile uses a message-list → detail flow; desktop retains a split-view experience.
- Search and category filters include announcements, availability, assignments, duties, broadcasts and system messages.
- Delivery metadata distinguishes planned channels from actual transport evidence.

### 8. Profile, communication preferences and notification health

- Profile is rebuilt in the approved visual language.
- Communication preferences distinguish announcements, liturgical availability, published assignments, community duties, broadcasts and urgent notices.
- Email is the default partner to PWA push.
- Notification Health checks install mode, browser permission, service-worker readiness, online state and the current device's actual Web Push subscription.
- Guided setup is Install KCFC → Enable Alerts → register/repair device → Send Test Notification.
- LINE, Telegram, future WhatsApp and Viber connector UX foundations remain feature-gated OFF.

### 9. Resources library

- Resources is rebuilt as a mobile-first searchable library.
- Authorized leaders can add trusted URLs/document references from a phone-friendly editor.
- Existing resource records remain compatible and private unless a future public-publishing gate is approved.

### 10. Treasury & Accounting migration

- The original accounting engine is preserved as `LegacyAccounting.tsx` for regression safety.
- `Accounting.tsx` provides the KCFC navy/royal-blue role-aware leadership shell.
- Treasury at a Glance separates approved balance/income/expenses from pending transactions.
- Existing transaction operations remain in the preserved engine.

### 11. Leadership & Admin migration

- The original administration engine remains preserved as `LegacyAdmin.tsx` under Advanced tools.
- The new Leadership workspace is decomposed into **Overview / Website Inquiries / Member Communications / Member Administration / Advanced Legacy Tools**.
- Website Inquiries provides search, unread/active/archive views and safe status updates without message deletion or automatic Gmail sending.
- Pending Member Approval verifies the existing profile only; it does not recreate Firebase Auth users or change roles/ministries.
- Roles & Ministries uses centralized `memberGovernance.ts` rules for President exclusivity, role limits, Core-member leadership/chore requirements, matching leader ministries, Choir exclusivity and the bounded dual-role rule.
- A new **read-only Core Member status planner** previews Regular↔Core transitions and shows exactly which roles/ministry assignments would be preserved or removed before any future status mutation is allowed.
- The Core-status planner performs no Firestore writes and cannot delete/recreate accounts.
- Actual Core-status changes, account disabling, member removal, credential purge and legacy Gmail inquiry replies remain isolated in Advanced tools.
- `core-status-transition-planning.md` records the transition semantics, safety decision and future write-workflow gates.

### 12. Communications architecture and routing policy

The approved routing hierarchy remains:

1. KCFC Inbox — durable source of truth.
2. PWA/Web Push — primary alert channel.
3. Email — default partner channel.
4. LINE — first optional Japan-focused secondary connector.
5. Telegram — additional optional connector.
6. WhatsApp — future/conditional.
7. Viber — low priority.
8. SMS — optional paid escalation only.

Announcements, liturgical availability/publication, community-duty notifications and leadership broadcasts progressively use the shared routing/batch/diagnostic foundation. Real PWA/Web Push and Gmail transport attempts are correlated to exact member Inbox records where supported without treating provider acceptance as final delivery.

### 13. Authentication / registration experience

- Login, registration and password-reset screens were rebuilt in the approved KCFC navy/royal-blue mobile-first design.
- Existing email/password sign-in, Google sign-in, registration, password reset, verification email and pending-member UID-preserving migration behavior remain available.
